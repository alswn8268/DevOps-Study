> ### ansible 초기 구성
> 1. 앤서블(패키지) 설치  -> sudo yum install -y ansible / ansible-core
    => ansible control-node 에서 설치
> 2. 작업 디렉토리 생성 -> mkdir XXX
> 3. 구성 파일 생성 (ansible.cfg) -> vim ansible.cfg (/etc/ansible/ansible.cfg)
    => ansible로 작업 시 어떤 방식으로 작업할지 결정
> 4. 인벤토리 생성  -> vim inventory
    => 작업 시 작업할 대상 시스템의 주소를 나열 
> 5. 사용자 생성 (암호 설정)  -> sudo useradd USER && sudo passwd USER
> 6. ssh 키 기반 인증 설정  -> ssh-keygen && ssh-copy-id USER@IP
    => 접속 시 편하고 안전하게 작업하기 위해 설정
> 7. sudo 권한 설정 -> sudo vim /etc/sudoers.d/USER (visudo)
    => root 권한의 작업이 필요한 경우 설정
> 8. 플레이북 작성 -> vim playbook.yaml
```

---
- name: 해당 플레이의 명칭 (작업 대상이 다르거나 설정을 다르게 사용하는 작업들을 각각 플레이로 작성)
  hosts: 작업할 대상 (servera, group01, all, localhost...)
  vars: -> 플레이 전체에 적용할 변수
    변수 이름: 변수 값
  tasks: 
    - name: 작업 이름 1
      모듈 이름: 
        속성 1: 변수 사용 시 {{}} 사용
       vars: -> 해당 작업만 적용
        변수 이름: 변수 값
    - name: 작업 이름 2
      모듈 이름: 
        속성 1: 
        속성 2: 
      when: 작업을 실행할 조건 지정
      loop:
        - value01
    - name: 작업 이름 3
      모듈 이름: 
        속성 1: 

- name: Play1
  hosts: all
  vars:
    myvars: value01
  vars_files:
    - vars/myvars.yaml
  tasks:
    - name: task1
    ansible.builtin.debug:
      msg: "{{ myvars }}"
    vars:
      myvars: value02
    when: myvars == "hello"
    loop:
      - value01
      - value02
...
```

# 6.3 핸들러 (Handler)
- 핸들러는 작업을 실행하고 시스템이 변경이 있을 때에 별도의 작업을 호출하고 실행하는 작업
```bash
[vagrant@ansible-controller-prac mywork]$ vi handler.yaml

---
- name: Test handler
  hosts: nodes
  vars:
    http_port: 80
  become: true
  tasks:
    - name: Apache Package Install
      ansible.builtin.yum:
        name: httpd
        state: latest
      notify:
        - Restart apache
  handlers:
    - name: Restart apache
      ansible.builtin.service:
        name: httpd
        state: restarted
...

[vagrant@ansible-controller-prac mywork]$ ansible-playbook handler.yaml
```

# 6.4 위임 (Delegation)
- Ansible은 기본적으로 호스트 패턴에 매칭되는 관리 노드나 그룹에서 모든 작업을 실행함
- 위임은 플레이 또는 일부 작업을 로컬(제어 노드)이나 다른 관리 노드에서 작업을 실행할 수 있음
- delegate_to 키워드로 특정 시스템을 지정하거나, local_action으로 로컬 실행을 설정할 수 있음
- serial 키워드로 관리 대상 시스템들을 그룹으로 나누어 순차적으로 작업을 실행할 수 있음
