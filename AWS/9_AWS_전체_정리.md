1. 클라우드 기본 개념
  - `인프라`: 서버와 네트워크와 스토리지 서비스 제공을 위해 구성하는 환경
  - `가상화`: 물리적인 리소스를 논리적으로 추상화
    `시스템 가상화`, `네트워크 가상화`, `스토리지 가상화`
    - `시스템 가상화`: 가상 머신, 컨테이너
    - `네트워크 가상화`: VLAN, 본딩/티밍, SDN, NFV, 브릿지
    - `스토리지 가상화`: RAID/LVM, 씬프로비저닝, SDS
  - `클라우드 컴퓨팅`: 언제/어디서든 네트워크를 통해 원하는 형태의 서비스를 제공
    초기 비용/시간 절감, 편하게 구성, 확장성/유연성/가용성에 유리... 퍼블릭
    - 구성 방식에 따른 분류 - 퍼블릭, 프라이빗, 하이브리드, 멀티
    - 서비스 제공 방식에 따른 분류 - IaaS, PaaS, SaaS

2. 서비스 종류
    1) `EC2`:
        컴퓨팅 서비스(IaaS) 중의 하나 - EKS / ECS, Lambda
        인스턴스(가상 머신)를 생성하고 사용하는 서비스
        생성 시 `이미지(AMI)`, `유형`, `VPC(네트워크)`, `EBS(스토리지)` 등을 구성
        - `이미지`: 부팅 가능한 운영체제가 설치된 디스크 파일 (교체 X)
                -> 이미지를 그대로 실행하기 때문에 초기 실행 속도가 빠름
        - `유형`: 인스턴스에 할당할 리소스의 크기/종류 (확장 가능)
        - `키 페어`: 이미지에서 제공하는 사용자로 접속하기 위해 필수 (암호X)
        - `가용 영역`: 가용성을 확보하기 위해 떨어져있는 데이터 센터
        - `보안 그룹`: 인스턴스에 대한 네트워크 트래픽 제어 규칙
    2) `VPC`:
        사용자 계정 및 리전 별로 독립적인 네트워크 환경을 제공
        각 VPC마다 네트워크 대역을 지정 -> 내부적으로 서브넷으로 분할
        서브넷은 퍼블릭 / 프라이빗으로 구분
        - `네트워크 ACL`: 각 서브넷에 대한 네트워크 트래픽 제어 규칙 (우선 순위 O)
        - `라우팅 테이블`: 서브넷마다 라우팅 경로를 설정
        - `인터넷 게이트웨이`: 외부 통신이 가능하도록 연결 구성
        - `NAT 게이트웨이`: 프라이빗 서브넷에서  인스턴스가 외부 통신이 필요할 때 사용
        - `S3 엔드포인트`: 프라이빗 서브넷에서 인스턴스가 S3에 접근 가능
        - `VPC 피어링`/`VPN`: 구성 등을 통해 VPC와 온프레미스 등을 서로 연결 가능
    3) `ELB`:
        부하 분산을 위해 사용하는 서비스
        - `ALB`: L7 로드밸런서, HTTP 트래픽에 대한 부하 분산 기능 지원 (서버)
        - `NLB`: L4 로드밸런서, TCP/UDP 트래픽에 대한 부하 분산 기능 지원 (서버)
        - `GWLB`: 트래픽을 보안 장비로 우선 전달, 확인 후 서버로 재전송 및 응답
        - `오토 스케일링`: 사용량에 따라 크기를 자동 조정
        - `대상 그룹`: 로드밸런서에 연결해 줄 인스턴스 그룹
        - `시작 템플릿`: 인스턴스 생성 방법에 대한 정의
        - `오토 스케일링 그룹`: 인스턴스 규모
    4) `EBS` / `S3` / `EFS`:
        `스토리지`: 데이터를 저장하는 장치
        스토리지 연결 방식 - DAS / NAS / SAN
        클라우드 스토리지 서비스 - `블록` / `오브젝트` / `파일 시스템 (공유)`
        - `블록 (EBS)` - 인스턴스에 볼륨 방식으로 연결해서 사용하는 서비스   
            -> 인스턴스의 데이터를 영구 저장  
            연결 시, 볼륨은 하나의 인스턴스에 연결 가능
            인스턴스 하나에는 여러 개의 볼륨 연결 가능
        - `공유 (EFS)`: 인스턴스에서 마운트만 해서 사용하는 스토리지
            -> 인스턴스의 데이터를 공유
            연결 시, 여러 개의 인스턴스에 동시 연결 사용
        - `오브젝트 (S3)`: 인스턴스와 무관하게 사용 가능
            사용 시, 버킷을 생성하고 해당 버킷에 파일(오브젝트)을 저장
            AWS 콘솔을 포함해서 URL 등으로 자유롭게 접근 가능
    5) `RDS` / `DynamoDB` / `ElasticCache` (데이터베이스 서비스)
        데이터 = 값, 정보 = 의미를 갖는 값
        데이터베이스 - 효율적으로 데이터 관리를 하기 위한 구조
        관계형 데이터베이스 - 2차원 테이블을 사용하는 데이터베이스
        SQL - 관계형 데이터베이스에서 사용하는 데이터 관리 표준 명령어
        DBMS - 데이터베이스를 관리해주는 시스템 (서비스)
        - AWS에서 제공하는 관계형 데이터베이스 서비스
            - `RDS`: AWS에서 관계형 데이터베이스를 관리형 서비스로 제공
            - `DynamoDB`: AWS에서 키-값 형태의 데이터베이스를 관리형 서비스로 제공
            - `ElasticCache`: AWS에서 인메모리 데이터베이스를 관리형 서비스로 제공
    6) `Route 53` / `CloudFront`
        - `DNS`: 이름으로 IP 주소를 찾을 수 있게 도와주는 서비스
        - `Route 53`: AWS에서 도메인 구매부터 레코드 관리 및 조회까지 기능 지원
        - `CDN`: 오리진 서버의 데이터를 임시 저장해두고 사용자에게 즉시 전달해주는 중간 매개체 역할의 캐시 서버
        - `CloudFront`: AWS에서 제공하는 CDN 서비스
    7) `IAM`
