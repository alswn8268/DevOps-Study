# 2.1 도커 개요
## 2.1.1 도커(Docker)란?
  - 리눅스 컨테이너를 관리하는 오픈소스 소프트웨어
  - 개발 환경, 테스트 환경, 서비스 환경을 모두 동일하게 사용할 수 있기 때문에 이식성이 좋음
### 2.1.1.1 서버를 코드 형태로 정의
  - 도커는 이미지를 제작할 때 코드 형태로 정의하여 작성할 수 있음
  -> 일관성 유지, 버전 관리 용이
### 2.1.1.2 이식성
  - 도커를 사용하면 컨테이너에 모든 환경을 구축하기 때문에 환경 통일에 용이
### 2.1.1.3 상호운용성
  - Google, Amazon, IBM 등 다양한 벤더 시스템 및 오픈 소스와 연계 가능

## 2.1.2. 도커의 구조
### 2.1.2.1 이미지
  - 컨테이너 실행에 필요한 파일 시스템과 설정 정보를 포함하는 읽기 전용 템플릿
### 2.1.2.2 저장소
  - 이미지를 저장하는 외부 저장공간
  - Public과 Private 저장소로 구분
### 2.1.2.3 컨테이너
  - 이미지의 실행 형태
  (이미지가 메모리에 올라가면 컨테이너, 컨테이너가 디스크에 저장되어 있으면 이미지)
  - 하나의 컨테이너에는 하나의 애플리케이션만 실행하는 것을 권장

## 2.1.3 도커의 기능
### 2.1.3.1 이미지 생성
  - 주로 Dockerfile로 이미지를 생성하며, 그 밖에는 docker commit 명령과 docker export/import 명령이 있음
### 2.1.3.2 이미지 공유
  - 도커는 저장소를 사용하여 이미지를 공유함
  - 도커 허브(Docker Hub)는 가장 대표적인 퍼블릭 저장소
### 2.1.3.3 컨테이너 생성
  - 컨테이너를 생성하고 네트워크 또는 볼륨과 같은 도커 오브젝트를 생성한 뒤 컨테이너에 연결할 수 있음
