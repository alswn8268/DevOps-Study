# 도커에서의 볼륨 연결
1. BindMount 방식
  - 호스트에 있는 디렉토리를 컨테이너에 공유
  - 연결 시 컨테이너(디렉토리) 내부에 파일이 존재한다면 보이지 않음
  - 연결 후에는 호스트에 있던 파일이 컨테이너 내부에서 접근 가능
  - 컨테이너 수정 / 추가 등의 데이터 변경 사항은 영구 저장
      -> 호스트의 디렉토리에 저장
2. Volume 방식
  - docker 명령어로 관리하는 특정 디렉토리 경로를 컨테이너에 공유
  - 연결 시 컨테이너(디렉토리) 내부에 파일이 존재했다면 보임
  - 연결 후에는 호스트에 있던 파일이 컨테이너 내부에서 접근 가능
  - 컨테이너 수정/추가 등의 데이터 변경 사항은 영구 저장
      -> 볼륨에 저장 (/var/lib/docker/volumes/볼륨명/_data)

### 컨테이너 볼륨 연결 실습 가이드
1. 빈 디렉토리 생성 후 해당 디렉토리를 컨테이너의 빈 디렉토리에 연결해보기
- 이미지는 ubuntu
- 컨테이너 이름은 shell01
- 연결할 컨테이너 디렉토리는 /mnt
- 연결할 호스트 디렉토리는 /tmp/contents (새로 생성)
```sh
vagrant@docker:~$ mkdir /tmp/contents
vagrant@docker:~$ docker container run -v /tmp/contents:/mnt --name shell01 -itd ubuntu:latest 
```

2. 볼륨이 연결된 디렉토리에서 파일 생성 및 확인 해보기
- shell01 컨테이너에서 /mnt 디렉토리에 새로운 파일 생성
- 파일 이름은 index.html
- 내용은 This is volume test (리다이렉트 사용)
```sh
vagrant@docker:~$ docker container exec shell01 touch /mnt/index.html
vagrant@docker:~$ docker container exec shell01 sh -c 'echo "This is volume test" > /mnt/index.html'
vagrant@docker:~$ docker container exec shell01 cat /mnt/index.html
This is volume test
```

3. 빈 디렉토리 생성 후 해당 디렉토리를 컨테이너의 /etc 에 연결해보기
- 호스트에 /tmp/empty-dir 디렉토리 생성
- 이미지는 ubuntu
- 컨테이너 이름은 shell02
- /tmp/empty-dir 디렉토리를 컨테이너의 /etc 디렉토리에 연결해서 실행
- /etc 디렉토리에 파일들 확인해보기
- /etc 디렉토리에 새로운 파일 하나 생성하기
```sh
vagrant@docker:~$ mkdir /tmp/empty-dir
vagrant@docker:~$ docker container run -v /tmp/empty-dir:/etc --name shell02 -itd ubuntu:latest 
vagrant@docker:~$ docker container exec shell02 ls /etc
vagrant@docker:~$ docker container exec shell02 touch /etc/newfile
```

    실행 파일 + 라이브러리 (파일 실행 시 필요한 부가적인 파일들)
- 컨테이너: 이미지를 실행한 상태 인스턴스
    이미지는 디스크 공간에 저장해둔 데이터
    실행 -> 디스크의 데이터를 메모리로 복사해서 저장
        저장된 데이터를 기반으로 CPU를 통해 연산 작업 수행
            -> 메모리의 데이터는 동작하면서 계속 수정 및 저장
    컨테이너 내부에서는 실행 파일(cmd)을 실행한 프로세스가 동작
- 볼륨: 컨테이너의 데이터는 임시 저장이므로 영구 저장을 원할 때 사용 가능
     컨테이너 및 호스트와 데이터(파일)를 공유

### docker 사용법
1. 컨테이너 관리
  - docker container run -> 컨테이너 생성 및 실행 (-it: 쉘을 필수, -d: 백그라운드)
  - docker container ls -> 컨테이너 목록 확인 (-a 옵션 사용 시 중지된 컨테이너도 확인 가능)
  - docker container rm -> 컨테이너 삭제 (중지된 컨테이너만 삭제)    
  - docker container stop -> 컨테이너 중지 (내부 프로세스 종료 시)
  - docker container start -> 컨테이너 시작 (중지된 컨테이너만 실행 가능)
  - docker container inspect -> 특정 컨테이너의 세부 항목 확인
  - docker container exec -> 컨테이너 내부에 명령어를 하나 더 실행 (해당 명령어가 종료되어도 컨테이너는 유지)
2. 볼륨 관리
  - docker volume create -> 새로운 볼륨 생성 (run 명령어에서 -v 옵션으로 지정 시 -> 자동 생성)
  - docker volume rm -> 볼륨 삭제 (연결되어있지 않은 볼륨만 삭제)
  - docker volume ls -> 볼륨 목록 확인
  - docker volume inspect -> 볼륨 세부 항목 확인 (경로 확인)
