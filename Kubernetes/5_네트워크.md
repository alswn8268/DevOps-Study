### 쿠버네티스의 네트워크 구성
- 파드들에 대한 네트워크 연결 구성은 되어있는 상태
- 파드마다 동적 IP 주소를 갖고 있음
  -> 접속에 어려움이 발생
- 서비스를 통해 고종 IP 주소를 공통적으로 하나 제공
  -> 단일 진입점
- 레플리카셋 등으로 파드를 실행할 경우 모든 파드는 동일한 목적의 애플리케이션이 동작
  -> 어디로 접속하도라도 결과는 동일
  가용성 및 부하 분산 등을 위해 여러 개의 파드를 생성
- 서비스 종류
  1. ClusterIP: 내부용 IP 주소만 할당해서 내부의 다른 파드가 접속할 때 사용
    -> 고정적인 단일 진입점을 위해 사용
  2. NodePort: 내부용 IP 주소도 할당하면서, 외부에서도 접속할 수 있도록 노드마다 포트포워딩 설정을 통해 지원
  3. LoadBalancer: 내부용 IP 주소도 할당하면서, 외부에서도 접속할 수 있도록 별도의 장치로 IP 주소 지원
    -----------> 파드에 접속하기 위한 용도
  4. ExternalName: 파드에서 외부(google 등)로 접속할 때 사용하는 별칭 기능 지원
    www.google.com 주소 대신 내가 만든 서비스 이름(gg 등)으로 접속 가능

### 서비스란?
- 동일한 애플리케이션이 동작하는 파드 집합들에 대한 접근 포인트 제공
  -> 단일 진입점, 고정 IP
  1. ClusterIP 서비스는 파드에서 파드로 접속할 때 사용 (내부용)
  2. NodePort, LoadBalancer 서비스는 외부에서 파드로 접속할 때 사용 (외부용)
    - NodePort는 사전 설정 없이 사용 가능, 특정 노드의 IP주소 및 30000 대역의 포트 번호를 사용
    - LoadBalancer는 별도의 IP 주소와 평소 사용하는 포트 사용, 사전 설정(별도 장치)이 필요

- 세션 어피니티: 한 번 접속했던 대상은 항상 동일한 파드로 접속하도록 설정
- 멀티 포트: 모든 서비스는 포트 번호를 여러 개 설정할 수 있음

서비스 설정에서 포트 번호 대신 이름으로 연결 구성이 가능
ExternalName 서비스로 외부 서버에 대한 DNS - CNAME 기능 지원

1.5 레디니스 프로브

----

프로브란?
- 파드(컨테이너)의 상태를 체크
  -> 상태에 따라 후속 조치

프로브 종류
- livenessProbe
  - 정상: 그대로 두고
  - 비정상: 재시작
- readinessProbe
  - 정상: 서비스의 엔드포인트에 파드 주소를 추가
  - 비정상: 서비스의 엔드포인트에 파드 주소를 제거

ex) 웹서비스를 구성
  1. 웹서비스가 동작하는 파드를 실행
    -> 레플리카셋으로 파드를 생성
    이유: 파드를 여러 개 생성하기 위해 레플리카셋 사용
    파드 하나에 문제가 있어도 다른 파드로 서비스 제공 가능
  2. 서비스 생성
    -> 클러스터 IP 종류로 생성
    이유: 내부(파드)에서 파드로 접속하기 위해 사용
    여러 파드에 대한 단일 진입점을 만들기 위해 생성
  3. 엔드포인트 등록
  -> 서비스의 셀렉터와 파드의 레이블이 일치하면 자동 등록
  4. readinessProbe 설정
  -> 엔드포인트 등록이 조건부 설정
  목적: 사용자가 정상적인 파드(웹서버)로 접속하도록 유도
