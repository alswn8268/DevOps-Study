# 2.1 쿠버네티스 아키텍처
## 2.1.1 컨트롤 플레인 (Control Plane)
  - 클러스터의 전체를 제어
  - 클러스터에 대한 전반적인 결정을 수행하고, 클러스터 이벤트를 감지하고 대응함
  - 반드시 3개 이상의 멀티 컨트롤 플레인 환경을 구성함

### 2.1.1.1 API 서버 (kube-apiserver)
  - 쿠버네티스 클러스터의 모든 구성 요소들은 컨트롤 플레인의 API 서버와 메시지를 주고받음
  - 컨트롤 플레인에 대한 프론트엔드를 담당

### 2.1.1.2 키-값 저장소 (etcd)
  - 쿠버네티스 클러스터의 모든 정보 데이터를 저장하는 일관성과 고가용성을 지원하는 키-값 저장소
  - 프로덕션 환경에서는 etcd 저장소의 데이터를 백업하는 계획이 필수적임

### 2.1.1.3 쿠버네티스 스케줄러 (kube-scheduler)
  - 스케줄러는 새로 생성되는 파드를 감지하고 이를 적절한 노드에 배치함
  - 파드를 어떤 노드에 배치할 지에 대한 스케줄링을 결정하기 위해 리소스의 요구 사항, 여러 가지 제약, 어피니티(Affinity) 등을 고려

### 2.1.1.4 쿠버네티스 컨트롤러 관리자 (kube-controller-manager)
  - 컨트롤러는 API 서버를 통해 클러스터의 상태를 감시하고 필요한 상태로 이행하는 기능을 가지는데, 컨트롤러 관리자는 이런 컨트롤러를 담당함
    - 노드(Node) 컨트롤러: 노드를 관리하며 노드가 다운되었을 때 알림과 대응을 함
    - 잡(Job) 컨트롤러: 일회성 작업을 나타내는 잡 오브젝트를 실행하고 감시함
    - 엔드포인트 슬라이스(EndpointSlice) 컨트롤러: 서비스와 파드를 연결함
    - 서비스 어카운트(Service Account) 컨트롤러: 쿠버네티스의 네임스페이스에 대한 계정 및 API 접근 제어
### 2.1.1.5 클라우드 컨트롤러 관리자 (cloud-controller-manager)
  - 클라우드를 제공하는 업체의 기능과 클라우드에서 동작하는 쿠버네티스 구성 요소와 상호작용할 수 있도록 하는 컨트롤러 관리자
    - 노드 컨트롤러: 클라우드 인프라의 컴퓨팅 리소스 관리 담당
    - 라우트 컨트롤러: 클라우드 인프라의 네트워크 경로 구성 담당
    - 서비스 컨트롤러: 클라우드 로드밸런서 관리 담당

## 2.1.2 (워커) 노드 (Worker Node) 
  - 컨테이너 런타임 환경을 제공
  - 동작중인 파드를 유지
### 2.1.2.1 kubelet
  - 각 노드에서 실행되는 에이전트로, 컨트롤 플레인으로부터 제공받은 파드의 구성 정보를 받아서 컨테이너를 동작시키고 관리
### 2.1.2.2 쿠버네티스 프록시(kube-proxy)
  - 호스트 레벨의 네트워크 규칙을 구성하고 외부 연결을 파드에 대한 포워딩을 담당
  - 쿠버네티스의 서비스 추상화가 가능하도록 함
### 2.1.2.3 컨테이너 런타임
  - 컨테이너 실행을 담당하는 구성 요소
  - 컨테이너 런타임 및 쿠버네티스 CRI 구현체를 지원

### 2.1.2.4 노드 상태 확인
```sh
kube ctl get nodes
```

### 정리
```
워크로드: 애플리케이션(컨테이너) 배포 단위
1. 파드(Pod)
  - 최소 관리 단위
  - 하나 이상의 컨테이너들의 집합
  - 하나의 애플리케이션 관리
2. 워크로드 리소스(Controller)
  - 파드의 상위 개체
  - 파드 관리 방법
    - 레플리카셋(rs): 파드의 복제분 개수를 지정하고 관리
    - 디플로이먼트(deployment): (레플리카셋의 상위 개체) 배포 정책 관리
    - 데몬셋(ds): 파드를 노드마다 하나씩만 배포
    - 스테이트풀셋(sts): 파드의 특성(상태)을 유지 -> 파드마다 고유성 봅장
    - 잡(job): 일회성 작업을 정해준 횟수만큼 반복 작업
    - 크론잡(cj): 일회성 작업을 정해준 시각에 반복 작업

네트워크
  - 서비스: 쿠버네티스에서 파드에 대한 네트워크 연결 구성
      - ClusterIP: 파드 간의 연결 구성 (내부용)
      - NodePort: 외부에서 파드로 연결 가능 (노드의 IP주소와 포트로 접근)
      - LoadBalancer: 외부에서 파드로 접근 가능 (별도의 IP주소로 접근)
      - ExternerName: 파드에서 외부로 접근 (CNAME 기능 지원)
  - 인그레스: 외부에서 파드로 접근 (L7 로드밸런싱)

스토리지
  - 볼륨: 파드의 특정 데이터를 영구 저장 및 공유
      - emptyDir: 임시 저장소 (파드 내부에 컨테이너끼리 공유)
      - hostPath: 각 노드들의 로컬 스토리지를 사용
      - NFS 등: 다양한 스토리지 서비스/제품을 지원 (외부 스토리지)
      - PV / PVC: 영구적인 스토리지 (쿠버네티스에서 관리하는 단위)
```
