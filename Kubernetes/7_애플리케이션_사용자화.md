### 애플리케이션 운영 과정
1. 개발자가 소스 코드를 작성
2. 코드를 실행파일로 컴파일 (빌드)
  2-2. 실행파일과 라이브러리를 포함한 컨테이너 이미지를 빌드
3. 실행파일(이미지)을 운영할 서버(쿠버네티스)에 배포(설치)
4. 실행파일(이미지) 실행  -> 컨테이너(파드)가 동작

기본적인 동작
  - 이미지에 설정해둔 EntryPoint와 cmd 항목을 실행
    -> 실행 시에는 기존 이미지에 설정해둔 환경 변수, 설정 파일 등 사용

사용자화
1. 이미지 사용자화
  - 이미지에 설정해둔 EntryPoint와 cmd 항목을 수정해서 실행
    -> EntryPoint 수정을 원하면 yaml 파일에서 command 사용
    cmd 수정을 원하면 yaml 파일에서 args 사용
  docker container run httpd:latest
    -> docker container run -it httpd:latest /bin/bash

2. 환경 변수 사용자화
  - 이미지에 설정해둔 환경 변수의 값을 수정하거나 새로운 환경 변수를 추가
    -> yaml 파일에서 env 항목으로 설정 (value / valueFrom)
  docker container run -e VARNAME=VALUE httpd:latest

쿠버네티스에서는 애플리케이션을 파드라는 단위로 배포 및 관리
파드를 관리하기 용이하도록 워크로드 리소스라는 개체로 관리
기본적으로 파드 실행 시 내부에는 컨테이너가 하나 이상 존재
컨테이너는 애플리케이션 운영을 위해 필요한 작업(동작)

  ex) 웹서버를 운영하기 위해 파드를 하나 생성
    -> 컨테이너로 하나는 웹서비스(apache/nginx/iis 등) 프로세스를 실행
    다른 컨테이너로는 index.html 파일을 주기적으로 수정 -> containers 항목에서 설정해서 계속 함께 동작
    혹은 git에서 index.html 파일 등을 다운로드 -> initContainer 방식으로 사전에 다운로드 
    => 서로 다른 컨테이너에서 데이터를 공유하기 위해 볼륨 (emptyDir)

컨테이너 실행 시에, 기존의 이미지 설정/파일을 그대로 사용하지 않고 수정해서 실행이 가능
  1. 이미지에서 설정해둔 EntryPoint와 cmd 항목을 yaml 파일에서 command / args 항목을 설정해서 수정이 가능
  2. 이미지에서 설정해둔 환경변수의 값을 수정하거나 새로운 환경변수를 추가 설정도 가능 (env)
  3. 기존 이미지에 없는 파일을 볼륨 형태로 공유(전달)해줄 수 있음 (pod.spec.containers.volumeMounts + pod.spec.volumes)
  -> 2번 / 3번 방식을 사용할 때, 컨피그맵과 시크릿을 사용할 수 있음

파드를 배포할 때에는 워크로드 리소스 단위로 배포하는 경우가 대부분
  1. ReplicaSet (rs) - 파드의 복제본 개수를 유지하도록 관리 (레이블/셀렉터를 통해 관리)
  2. Deployment (deploy) - ReplicaSet을 관리 (설정이 변경되거나 하는 경우 해당 설정이 반영되도록 파드를 재생성)
    => 대부분의 애플리케이션을 배포할 때에 Deployment를 사용해서 배포하는 경우가 많음
  3. DaemonSet (ds) - 노드마다 하나씩의 파드만 유지
  4. StatefulSet (sts) - 파드의 고유성을 유지
  5. Job (job) - 일회성 파드를 원하는 횟수만큼 완료할 수 있도록 보장
  6. CronJob (cj) - 일회성 파드를 주기적으로 반복수행하도록 보장
