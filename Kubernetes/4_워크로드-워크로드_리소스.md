### 개요
쿠버네티스는 워크로드 리소스라는 추상화된 상위 리소스를 정의해 파드를 관리함. 이를 통해 파드의 생성, 삭제, 스케일링, 업데이트, 롤링 업데이트, 롤백 등을 쉽게 관리할 수 있음.

- 워크로드: 애플리케이션 배포 방식(단위)
- 파드: 최소 관리단위일 뿐이고 실제로는 파드 단위의 배포는 X
- 워크로드 리소스: 파드의 상위 개체 (파드를 관리)
  - 레플리케이션 컨트롤러
  - 레플리카셋: 파드의 복제본 개수를 관리 (절대값)
  - 디플로이먼트: 레플리카셋의 상위 개체 (배포 정책 관리)
  - 스테이트풀셋: 파드의 상태를 유지
  - 데몬셋: 파드의 복제본 개수를 관리 (노드 당 하나씩)
  - 잡: 일회성 작업을 즉각적으로 수행
  - 크론잡: 일회성 작업을주기적으로 반복 수행

1. 리소스 생성 -> 확인 (워크로드 리소스 / 파드)
2. 생성된 파드 중 하나를 삭제 -> 확인 (파드 개수)
3. 레이블을 변경 -> 확인 (레이블을 변경한 파드, 그 외의 파드, 워크로드 리소스)
4. 수동 스케일링 -> 확대 / 축소를 통해 개수 확인
5. 워크로드 리소스 삭제 -> 확인 (워크로드 리소스 / 파드)

```sh
vagrant@kube-control1:~$ mkdir controller

vagrant@kube-control1:~/controller$ vim myapp-rs.yaml

apiVersion: apps/v1            # ReplicaSet이 속한 API 그룹/버전
kind: ReplicaSet               # 워크로드 타입: ReplicaSet
metadata:
  name: myapp-rs               # ReplicaSet 이름
spec:
  replicas: 3                  # 유지할 파드 개수 (항상 3개)
  selector:                    # ReplicaSet이 관리할 파드 선택 기준
    matchLabels:
      app: myapp-rs            # app=myapp-rs 라벨을 가진 파드만 관리
  template:                    # ReplicaSet이 새로 만들 파드의 설계도
    metadata:
      labels:
        app: myapp-rs          # selector와 반드시 동일해야 함

        - name: myapp          # 컨테이너 이름
```

### 레플리카셋으로 파드 생성시 레이블 / 셀렉터 설정
1. 레이블 1개, 셀렉터 1개 식으로 양쪽 모두 동일한 경우 -> 생성 O
2. 레이블 1개, 셀렉터 2개 식으로 셀렉터가 개수가 많은 경우 -> 생성 X
3. 레이블 2개, 셀렉터 1개 식으로 셀렉터가 개수가 적은 경우 -> 생성 O
