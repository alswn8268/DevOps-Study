### 스테이트풀셋
- 파드들의 고유한 상태를 구분/유지가 가능한 워크로드 리소스
- 파드들 중에 특정 파드에 접속을 원하는 경우
  -> 헤드리스 서비스와 함께 사용
- 파드마다 고유한 볼륨을 연결하고자 하는 경우
  -> 스테이트풀셋 매니페스트파일(YAML)을 설정할 때, volumeClaimTemplate 항목을 설정 (별도의 pvc 생성 X)

실습 정리
1. 디플로이먼트와 ClusterIP 서비스를 연결
  -> 서비스에 고정 IP 주소가 할당, 서비스 이름으로 DNS 등록, 서비스 엔드포인트에 각 파드가 추가
  접속은 서비스의 IP 주소 또는 서비스 이름으로 가능하고, 접속시 각 파드로 분산
2. 스테이트풀셋과 ClusterIP 서비스를 연결
  -> 서비스에 고정 IP 주소가 할당, 서비스 이름으로 DNS 등록, 서비스 엔드포인트에 각 파드가 추가
  접속은 서비스의 IP 주소 또는 서비스 이름으로 가능하고, 접속시 각 파드로 분산
3. 디플로이먼트와 헤드리스 서비스를 연결
  -> 서비스에 고정 IP 주소가 없음, 서비스 이름으로 DNS 등록, 서비스 엔드포인트에 각 파드가 추가
  접속은 서비스 이름으로 가능하고, 접속시 각 파드로 분산
4. 스테이트풀셋과 헤드리스 서비스를 연결
  -> 서비스에 고정 IP 주소가 없음, 서비스 이름으로 DNS 등록 + 파드 이름으로도 DNS 추가, 서비스 엔드포인트에 각 파드가 추가
  접속은 서비스의 IP 주소 또는 서비스 이름으로 가능하고, 접속시 각 파드로 분산 (X)
  접속은 파드 이름 + 서비스 이름(DNS)으로 가능 -> 특정 파드로 접속이 가능

5. 디플로이먼트에 PVC 연결
  설정시, 디플로이먼트 yaml 파일에서는 pod.spec.container.volumeMounts + pod.spec.volumes 설정
  volumes 항목에는 PVC 이름만 설정, 별도로 PVC yaml 파일을 따로 생성
  -> 파드 전체에 대해서 하나의 PV/PVC만 만들어서 연결(공유)
6. 스테이트풀셋에 PVC 연결
  설정시, 스테이트풀셋 yaml 파일에서 pod.spec.container.volumeMounts + volumesClaimTemplate 설정
  volumes 항목에는 PVC 이름만 설정, 별도로 PVC yaml 파일을 따로 생성
  -> 파드마다 PV/PVC를 하나씩 만들어서 연결

```sh
vagrant@kube-control1:~/controller$ vim  myapp-deploy-pvc.yaml

apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp-deploy-pvc
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp-deploy-pvc
  template:
    metadata:
      labels:
        app: myapp-deploy-pvc
    spec:
      containers:
        - name: myapp
          image: ghcr.io/nobreak-labs/go-myweb:alpine
          volumeMounts:
            - name: test-pvc
              mountPath: /mnt
      volumes:
        - name: test-pvc
          perseistentVolumeClaim:
            - name: deploy-pvc

vagrant@kube-control1:~/controller$ vim pvc-deploy.yaml

kind: PersistentVolumeClaim
apiVersion: v1
metadata:
  name: deploy-pvc
spec:
  storageClassName: nfs-client
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 1Gi

vagrant@kube-control1:~/controller$ kubectl create -f pvc-deploy.yaml
```

```sh
vagrant@kube-control1:~/controller$ vim myapp-sts-vol.yaml

apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: myapp-sts-vol
spec:
  selector:
    matchLabels:
      app: myapp-sts-vol
  serviceName: myapp-svc-headless
  replicas: 3
  template:
    metadata:
      labels:
        app: myapp-sts-vol
    spec:
      containers:
        - name: myapp
          image: ghcr.io/nobreak-labs/go-myweb:alpine
          ports:
            - containerPort: 8080
          volumeMounts:
            - name: myapp-data
            mountPath: /data
  volumeClaimTemplates:
    - metadata:
        name: myapp-data
      spec:
        accessModes: ["ReadWriteOnce"]
        resources:
          requests:
            storage: 1Gi
        storageClassName: nfs-client

vagrant@kube-control1:~/controller$ kubectl create -f myapp-sts-vol.yaml
```
