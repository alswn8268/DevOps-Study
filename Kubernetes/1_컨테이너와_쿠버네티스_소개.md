# 1.1 마이크로서비스 등장 배경 및 DevOps
## 1.1.1 모놀리식 아키텍처 (Monolithic Architecture)
  - 대부분 단일 프로세스에서 실행되거나 몇몇 시스템에서 몇 개의 프로세스로 실행되는 거대한 모놀리식 애플리케이션
  - 개발, 배포가 간단하고 확장성이 단순하다는 장점이 있음
  - 코드 품질이 낮아짐, 애플리케이션 시작이 오래 걸림, 지속적 배포가 어려움, 확장이 어려움, 컴포넌트별 개발이 어려움 등의 단점이 있음
  - 모놀리식 애플리케이션은 모든 것이 서로 강하게 결합해 구성되어 단일 OS의 단일 프로세스로 실행되기 때문에 모든 것을 하나의 애플리케이션으로 개발, 배치 관리 되어야 함 -> 작은 추가 및 변경에도 전체를 재배포 해야야 하며, 장기적으로 시스템이 점점 복잡해져 전체적인 품질 저하가 발생할 수 있음
## 1.1.2 마이크로서비스 아키텍처
  - API를 통해 기능적으로 세분화되고 독립적으로 작동하는 방식

# 1.2 컨테이너 소개
## 1.2.1 컨테이너란
  - 운영체제에서 실행되는 프로세스를 격리(Isolation)하여 별도의 실행 환경을 제공해주는 기술

# 1.3 쿠버네티스 소개
## 1.3.1 쿠버네티스란
  - 컨테이너 기반의 분산 클러스터 환경을 제공하며 워크로드를 위해 컴퓨팅, 네트워킹 및 스토리지 인프라를 오케스트레이션(Orchestration)함
