# 3.1 YAML 및 오브젝트 기본

# 3.2 파드 (Pod)
  - 쿠버네티스 워크로드 리소스 중 배포할 수 있는 가장 작은 단위
  - 쿠버네티스 클러스터 내에서 애플리케이션을 배포하며 동작하는 프로세스
## 3.2.1 파드 기본
  - 주로 두 가지 방법으로 사용됨
      - 단일 컨테이너만 동작하는 파드
      - (함께 동작하는 작업이 필요한) 다중 컨테이너가 동작하는 파드
## 3.2.2 파드 생성 및 목록 확인

```sh
vagrant@kube-control1:~$ mkdir pod
vagrant@kube-control1:~$ cd pod
vagrant@kube-control1:~/pod$ vim myapp-pod.yaml

apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
spec:
  containers:
    - name: myapp
      image: ghcr.io/nobreak-labs/go-myweb:alpine
      ports:
        - containerPort: 8080
          protocol: TCP

# 현재 클러스터에서 사용할 수 있는 모든 리소스 종류 조회
vagrant@kube-control1:~/pod$ kubectl api-resources
...
pods                                po           v1                                  true         Pod
# pod 리소스의 공식 구조 설명
vagrant@kube-control1:~/pod$ kubectl explain pod 
# pod 중에서도 spec 영역만 상세 설명
vagrant@kube-control1:~/pod$ kubectl explain pod.spec
```

```sh
vagrant@kube-control1:~/pod$ kubectl create -f myapp-pod.yaml
pod/myapp-pod created

# vagrant@kube-control1:~/pod$ kubectl replace -f myapp-pod.yaml # 내용물 편집 후 실행

# create를 두 번 하면 오류가 발생하지만 apply를 두 번하면 오류가 발생하는 대신 기존의 대상이 수정될 수 있음
```

# 3.6 파드의 생명 주기와 프로브
- 파드는 `Pending`->`Running`->`Succeed` 또는 `Failed` 값을 가짐
- `kubelet`은 파드의 컨테이너 상태를 추적하고, 오류가 발생하면 정상 상태로 만들기 위한 조치로 컨테이너를 재시작할 수 있음
- 파드는 최초 생성될 때 한 번만 스케줄링되며, 특정 노드에 할당되면 파드는 중지나 종료될 때까지 같은 노드에서 실행됨
## 3.6.1 파드의 생명 주기
  - 파드는 임시 워크로드 리소스이며, 파드가 생성되면 식별용 고유 UID가 할당되고 종료될 때까지 특정 노드에서만 실행됨
### 3.6.1.1 파드의 단계 확인
  - 파드의 단계는 `kubectl get pods` 명령어 결과로 확인할 수 있음
### 3.6.1.2 파드의 단계
  - Pending
    - 파드가 클러스터에서 승인되었지만, 실행되고 있지 않음
    - 파드가 스케줄링되기 전
    - 이미지 풀링
  - Running
    - 파드가 노드에 할당됨
    - 하나 이상의 컨테이너가 실행 중
    - 시작 또는 재시작 중
  - Succeeded
    - 모든 컨테이너가 정상적(zero)으로 종료
    - 재시작되지 않음
  - Failed
    - 모든 컨테이너가 종료
    - 하나 이상의 컨테이너가 실패(non-zero)로 종료
  - Unknown
    - 알 수 없음
    - 일반적으로 노드와의 통신 오류
  
  (* 일반적으로 파드 삭제 시 Terminating 상태로 표시되나, 이는 파드의 단계에 해당하지 않음)

## 3.6.2 컨테이너 상태
### 3.6.2.1 컨테이너 상태 확인
  - kubelet은 각 컨테이너의 상태도 모니터링 함
  - 컨테이너의 상태는 `kubectl describe pod` 명령의 결과로 확인할 수 있음
### 3.6.2.2 컨테이너 상태
  - Waiting
    - 컨테이너가 Running 또는 Terminated 상태가 아님
    - 컨테이너 시작 전 필요한 작업 중 (이미지 풀링, 스토리지 연결 등)
  - Running
    - 실행 중
    - 해당 상태가 된 시각 표시
  - Terminated
    - 컨테이너 실행이 완료됨
    - 실패
    - Reason 필드에 이유 표시
    - 해당 상태가 된 시각 표시

## 3.6.3 컨테이너의 재시작 정책
  - 모든 컨테이너는 오류 발생 시 재시작을 하기 위한 재시작 정책을 가지고 있음
### .spec.restartPolicy 재시작 정책
  - Always: (기본 값) 종료 / 실패 시 항상 재시작
  - Onfailure: 실패 시 재시작 (정상 종료 시 재시작하지 않음)
  - Never: 재시작하지 않음
### 3.6.3.1 지수 백오프(Exponential Back-off) 지연 시간
  - 파드의 컨테이너 재시작은 최대 300초로 제한된 지수 백오프 지연 시간을 순차적으로 가지며 재시작함

## 3.6.4 컨테이너 프로브 개요
- 컨테이너 프로브는 kubelet이 컨테이너를 주기적으로 진단하는 프로브 핸들러를 호출함

```sh
vagrant@kube-control1:~/pod$ cp myapp-pod.yaml myapp-pod-restart.yaml
vagrant@kube-control1:~/pod$ vim myapp-pod-restart.yaml
...
metadata:
  name: myapp-pod-restart
spec:
  containers:
    - name: myapp
      image: ghcr.io/nobreak-labs/go-myweb:alpine
      ports:
        - containerPort: 8080
          protocol: TCP
  restartPolicy: Never
...

vagrant@kube-control1:~/pod$ kubectl create -f myapp-pod-restart.yaml

vagrant@kube-control1:~/pod$ kubectl describe pod myapp-pod-restart
```

### 3.6.4.1 프로브 핸들러
  - HTTPGetAction
    - 특정 경로에 HTTP GET 요청
    - HTTP 응답 코드가 2XX 또는 3XX인지 확인
  - TCPSocketAction
    - 특정 TCP 포트 연결
    - 포트가 활성화되어 있는지 확인
  - ExecAction
    - 컨테이너 내의 지정된 바이너리를 실행
    - 명령의 종료 코드가 0인지 확인

### 3.6.4.2 프로브 결과
  - Success
  - Failure
  - Unknown

### 3.6.4.3 프로브 종류
  - livenessProbe
    - 컨테이너가 동작 중인지 확인
    - 진단에 실패하면 재시작 정책을 적용
    - livenessProbe를 선언하지 않으면, 기본 상태는 Success
  - readinessProbe
    - 컨테이너가 요청을 처리할 준비가 되었는지 확인 
    - 진단에 실패하면 엔드포인트 컨트롤러는 파드의 IP 주소를 엔드포인트에서 제거
    - readinessProbe를 선언하지 않으면, 기본 상태는 Success
  - startupProbe
    - 컨테이너 내의 애플리케이션이 시작되었는지 확인
    - startupProbe가 선언되었을 경우, 진단을 통과하기 전까지 다른 프로브를 활성화하지 않음

```sh
vagrant@kube-control1:~/pod$ cp myapp-pod.yaml myapp-pod-liveness.yaml
vagrant@kube-control1:~/pod$ vim myapp-pod-liveness.yaml

vagrant@kube-control1:~/pod$ kubectl explain pod.spec.containers | grep Probe
  livenessProbe <Probe>
```
